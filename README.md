# discord-bot

このボットは、Discord サーバーのチャンネル管理、バックアップ/復元、通話時間の記録と、OpenAIによる会話履歴への質問・要約を提供します。

## できること
- `@tti-intelligence 質問` でサーバーの公開チャンネルを必要に応じて横断し、会話履歴を踏まえて返信
- `/ask question:質問 [channel:対象]` で履歴を調べ、参照元リンク付きで本人だけに回答（既定モデル: `gpt-6.1-sol`）
- `.docx` を添付して入力欄を埋めるよう頼むと、記入済みWordを返信
- 先にチャンネルへ投稿した `.txt`・`.pdf` を、返信元や履歴から読み込んで参照
- Botの回答に返信すると、メンションなしで会話を継続
- `/postpanel` でチャンネル操作パネルを投稿
- `/categorylock add/remove/list` でカテゴリロックを管理
- `/resetchannelquota [user]` でチャンネル作成回数をリセット
- `/backup` でサーバー情報とテキストチャンネルのメッセージ履歴を JSON 形式でバックアップ
- `/restorebackup` でバックアップJSONを読み込んで、チャンネルとメッセージ履歴を別サーバーに復元
- `/postvoicestats` で「誰がどれだけ通話に入っていたか」を社畜時間として記録するパネルを投稿し、更新ボタンで最新状態へ更新できます

## 使い方
1. `.env` に `DISCORD_TOKEN` と `GUILD_ID` を設定します。
2. 必要に応じて `BACKUP_CHANNEL_ID` を設定すると、バックアップファイルをそのチャンネルにも送信できます。
3. 必要に応じて `BACKUP_MAX_MESSAGES_PER_CHANNEL` を設定すると、1チャンネルあたりのバックアップメッセージ数を調整できます（既定値: 2000）。
4. `npm install`
5. `npm start`

## AI機能の設定

1. `.env.example` を参考に、`.env` に `OPENAI_API_KEY` を設定します。既存の `.env` は上書きせず、`DISCORD_TOKEN` と `GUILD_ID` も保持してください。`.env` はGit管理対象外です。
2. Discord Developer Portalで対象アプリの **Bot → Privileged Gateway Intents → Message Content Intent** を有効にします。無効のままAPIキーを設定して起動すると、Gatewayの接続が拒否されます。対象BotがDiscordの承認を必要とする場合は、Intentの承認も必要です。
3. Botに **View Channel / Read Message History / Send Messages** を付与します。スレッド内で返信する場合は **Send Messages in Threads** も必要です。インストール時のスコープには `bot` と `applications.commands` を含めます。
4. Botを再起動します。起動時に `GUILD_ID` のサーバーへ `/ask` が登録されます。

Renderなどで稼働させている場合は、そのサービスの環境変数にも `OPENAI_API_KEY` を設定して再デプロイしてください。ローカルの `.env` は自動的には反映されません。OpenAI APIキーをDiscordの投稿やGitへ貼り付けないでください。

### 使用例

- `@tti-intelligence このチャンネルの決定事項と未完了のTODOをまとめて`
- Botの回答に返信して `この話の続きで、次に何をすればいい？`（メンション不要）
- PDFを添付して `@tti-intelligence このPDFの表を要約して`
- `/ask question:リリース日の相談はどのチャンネルでしていた？`
- `/ask question:今週決まったことを教えて channel:#開発`

メンション・Botへの返信には同じ場所で返信します。必要に応じてサーバー内の公開チャンネルも参照します。別チャンネルの情報を公開する際は、全員が履歴を読めることと閲覧を拒否する上書き権限がないことを確認します。非公開チャンネルは `/ask` で質問者本人にだけ回答し、質問者とBotの両方の閲覧権限を確認します。Botへの返信は同じチャンネル内の返信元を最大8段階たどり、文章と対応する添付を引き継ぎます。他人や別のBotへの通常の返信には反応しません。

Discordの候補からBotを選ぶ正式なメンションと、投稿の先頭に文字として入力した `@tti-intelligence 質問` の両方に反応します。従来の `@tti intelligence 質問` も利用できます。通常の会話中に名前が出てきた場合や、メールアドレス・似た別名には反応しません。

質問を処理している間は、質問元の投稿に 🤔 を付けます。回答時やエラー終了時にBot自身のリアクションだけを外します。Botに **Add Reactions（リアクションの追加）** 権限がない場合も、回答処理は継続します。

### txtを先に置いてWordを埋める

1. 参考にする `.txt` をチャンネルへ投稿します。
2. その投稿の **返信** を選び、入力用の `.docx` を添付します。
3. `@tti-intelligence この枠をチャットと返信元のtxtの内容で埋めて` と送ります。
4. Botが同じチャンネルの会話とtxtを参照して、`元の名前_記入済み.docx` を返します。

返信元をたどるのは同じチャンネル内で最大8段階です。Wordとtxtを同じ投稿に添付する使い方もできます。返信を付けず `先に置いた議事録.txtを使って` と頼むと、取得した直近履歴からtxt投稿を探して本文を読みます。古いtxtが見つからない場合は、その投稿へ返信する方法が確実です。

入力対象は、表の空セル、`{{概要}}`・`{{担当者}}` のような差し込み欄、テキスト型コンテンツコントロール、空のテキストボックスです。既存の見出し・罫線・文字書式を保ちます。表の行に固定の高さがある場合は、記入文が切れないよう最小の高さへ変更します。既存の回答が入ったセル・記入済みのテキスト入力欄・単なる余白の段落は上書きしません。画像として描かれた枠・旧形式 `.doc`・マクロ・署名・編集保護・日付選択やチェックボックスなどの特殊な入力欄には対応していません。

Wordは1回に1個、8MB以下、入力欄は40個までです。txtは1個8MB以下で、UTF-8・UTF-16・Shift JISに対応します。読み込む添付はWord・txt・PDFを合わせて4個まで、Wordの抽出本文は各最大16,000文字・合計約40,000文字です。txtはこの文字数制限とは別枠で、UTF-8換算で合計8MBまでの全文をまとめてSolへ渡します。txtは先頭だけに切り詰めません。64KBを超えるtxtでは、会話・指示・ツールを含む入力全体をOpenAIの入力トークン計数APIで確認し、90万トークンを超えたら全文を切り捨てずサイズ超過を案内します。長文は入力に比例してAPI利用料が増え、272K入力トークン超ではSolの長文料金が適用されます。通常の入力欄は800文字、固定サイズのテキストボックス内は160文字までに抑えます。枠の幅と位置は変更しないため、特殊なレイアウトはWordで確認してください。会話やtxtに根拠がない項目は、情報がないことを記載します。

元のWord投稿に返信して `@tti-intelligence これできますか`・`Wordで返して` と頼む場合も、入力欄があれば記入済みWordを返します。履歴から読み込んだ入力用Wordも対象になります。`/ask` で頼んだ場合はWordの添付も本人だけに返します。文章の要約・内容確認だけの質問では入力欄を変更しません。

Wordを返すには、Botに **Attach Files（ファイルを添付）** 権限も必要です。添付と完成したWordはメモリ内で扱い、Botのディスクには保存しません。添付Word内の文章やtxtを、Botの動作を変更する命令としては扱いません。

### PDFを読む

PDFを依頼と一緒に添付するか、PDFを置いた投稿に返信してメンションしてください。履歴にあるPDFも `先に置いた資料.pdfを読んで` と指定できます。PDFは文字とページ画像をSolへ渡すため、表・図・スキャンも対象になります。小さい文字や不鮮明な画像は読み取れないことがあります。1個8MB以下、1回2個・合計12MBまでです。PDFの容量は文章の文字数予算とは別で、ページ数に応じてAPIの利用量が増えます。破損・パスワード付きのPDFは読めない場合があります。PDFの内容をWord記入の資料にすることもできます。Botのディスクには保存しません。

### 簡単な依頼の振り分け

`CEREBRAS_API_KEY` がある場合、あいさつ、短い四則計算、`英訳：こんにちは` のような短い明示的な文章変換をCerebrasへ送ります。この経路では質問の本文だけを送り、Discordの会話履歴や添付は渡しません。返信先・添付がある依頼、履歴の質問、Word作成、それ以外の依頼はGPT-6.1 Solを使います。Cerebrasでエラー・時間切れ・不完全な出力があった場合もSolへ戻します。

`/ask` の回答は、長い回答の続きも含めて本人だけに表示します。`channel` を指定するとその場所だけを参照します。省略すると現在のチャンネルの直近履歴を読み、必要に応じて質問者とBotの両方が閲覧・履歴参照できるチャンネルを調べます。非公開スレッドは参加状況またはスレッド管理権限も確認します。チャンネル一覧にはテキスト・アナウンス・ボイスチャンネルのテキストチャット、取得したアクティブなスレッド（フォーラム投稿を含む）、認識済みスレッドが含まれます。音声の録音や文字起こしはしません。未認識のアーカイブ済みスレッドを網羅的に探索することはありません。

履歴は質問時に取得します。常時収集や独自の履歴データベースはありません。検索は選んだチャンネルの直近履歴を文字列で照合する方式で、Discord全履歴の検索ではありません。AIは取得したメッセージのIDを使って古い履歴や対応する添付を追加取得できますが、調査回数と入力サイズには上限があります。画像・埋め込み・転送先の投稿は読み取りません。

`/ask` の非公開回答は次回の質問には保存しません。続きの質問では必要な条件をもう一度書いてください。公開のメンション会話は、同じ場所の直近履歴として再取得されます。Botの回答に返信した場合は、返信元の会話や添付も参照します。

通常の依頼では、質問と取得したメッセージ本文・投稿者名・日時・リンク・添付名・読み込んだtxt/Wordの本文と入力欄・PDFそのものをOpenAI APIへ送信します。Responses APIには `store: false` を指定します。簡単な依頼は上記の範囲でCerebras APIへ送信します。Bot側ではAI用の会話履歴をディスクに保存しません。既存のバックアップ機能は別です。

### AIの環境変数

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `OPENAI_API_KEY` | なし | 未設定なら既存の管理機能だけで起動。`/ask` は設定案内を返します |
| `OPENAI_MODEL` | `gpt-6.1-sol` | 履歴調査・Word記入などを担当するOpenAIのモデルID |
| `CEREBRAS_API_KEY` | なし | 簡単な依頼の振り分けを有効にするキー |
| `CEREBRAS_MODEL` | `qwen-3.8-27b` | 簡単な依頼を担当するCerebrasのモデルID |
| `AI_ALLOWED_CHANNEL_IDS` | 制限なし | 参照・利用を許可するチャンネルIDのカンマ区切り。親チャンネルを許可すると配下のスレッドも対象 |
| `AI_HISTORY_LIMIT` | `50` | 1回の履歴取得で読む直近件数（1〜200件） |
| `AI_MAX_OUTPUT_TOKENS` | `2000` | API呼び出し1回の出力上限。推論も含みます（256〜4096） |
| `AI_COOLDOWN_SECONDS` | `15` | 同一ユーザーの連投間隔（0〜3600秒） |
| `AI_MAX_CONCURRENT` | `2` | 同時処理する質問数（1〜4） |

1つの質問で調査ツールは最大6回、OpenAI APIは通常最大7回、Word記入時は最大8回呼び出します。検索ツール1回で最大5チャンネルを調べます。履歴の本文は1投稿1,800文字、履歴・Word本文などの入力資料は合計約60,000文字に制限します。txt全文とPDF入力はこの文字数枠とは別です。長いtxtの入力サイズ確認は回答生成とは別のHTTPリクエストで、生成を分割する処理ではありません。各質問のAPI接続には共通の120秒の期限があります。Cerebrasの応答期限は10秒です。設定範囲外の数値は既定値に戻ります。これらは利用量を抑えるための制限で、月額料金の上限ではありません。

### 動作確認

```sh
npm run check
npm test
npm run test:openai
npm run test:cerebras
```

`test:openai` は実際のOpenAI APIに短い質問を1回送ります（API利用料が発生します）。キーやDiscordの履歴は出力せず、接続結果・モデル名・トークン数だけを表示します。Discordの設定後は実サーバーでメンションと `/ask` の両方を試してください。

`npm run test:openai -- --tools` では、ツール呼び出しと結果を渡した後の回答までを2回のAPI通信で確認できます。

## バックアップファイル
`/backups` ディレクトリに JSON ファイルとして保存されます。

## 復元について
`/restorebackup` はバックアップJSONファイルを添付して実行します。テキストチャンネルを再作成し、メッセージ履歴を時系列で再送信します。
